\section{Preliminaries}
\label{sec:prelim}

Notation, used consistently throughout: $d=128$ is the code length (never a distance bound), $N$ the
database size, $\xt,\yt \in \{0,1\}^d$ the client and server codes, $H$ their Hamming distance, and
$\ell_i$ record $i$'s label; the FLPSI matcher draws $T$ sub-samples of $w$ positions each and accepts
at $t$ collisions, with per-sub-sample collision probability $q(H)$, colliding-mask count $K$, and mask
$m_j$; $P_{\mathrm{gen}},P_{\mathrm{imp}}$ are the genuine and impostor Hamming laws, $\mathbb{F}$ the
secret-sharing field, and $\lambda,\kappa$ the computational and statistical security parameters.

\subsection{What we build on}

CKKS~\cite{CKKS17} does approximate arithmetic on encrypted real vectors, but any inner product needs
slot rotations and hence Galois keys that dominate key material; Blind-Touch~\cite{ChoiWooKim24}
applies this to fingerprint matching, at a 117\,MB Galois key per client, an 856\,KB query ciphertext,
and a 512-users-per-ciphertext packing limit. Our extractor is the Blind-Touch Siamese
network~\cite{ChoiWooKim24,KimOhKim20}, a shared convolutional trunk trained with pairwise
binary cross-entropy on identity-disjoint splits so that same-identity pairs land close. We reuse it
unchanged; the architecture is not a contribution. What matters is that its output is a real vector
whose training-metric distance tracks identity, and that it must become a fixed-length binary code
before a fuzzy-PSI matcher can consume it.

\subsection{Fuzzy-labelled PSI: functionality and accept model}
\label{sec:flpsi-prelim}

Fuzzy-labelled PSI (FLPSI) was introduced by Uzun et al.\ for private real-time biometric
search~\cite{UzunEtAl21}: a client holding $\xt \in \{0,1\}^{d}$ learns the label $\ell_i$ of any
server record $\yt_i$ within a Hamming ball of the query, while the server learns only whether a
match occurred. We take the functionality and accept model from Uzun et al.; the concrete efficient
backend is Bui and Cong's vector ring-OLE construction~\cite{BuiCong25}, built on the VOLE-PSI
line~\cite{RindalSchoppmann21} and silent OT/PCG~\cite{BoyleEtAl19}.

The matcher has two parts. A \emph{masked OPRF} evaluates a keyed PRF on sub-sampled positions, so
equality of the PRF images certifies equality on those positions without revealing the bits: the
parties agree on $T$ public masks $m_j$ of weight $w$, and sub-sample $j$ restricts a code to the
positions of $m_j$. A \emph{threshold labelled PSI} turns collisions into a label: the server Shamir-
shares each $\ell_i$~\cite{Shamir79}, attaches one share per mask, and delivers them through a
polynomial encoding evaluated obliviously via the OLE/VOLE backend, so a client colliding on at least
$t$ masks reconstructs $\ell_i$ and one colliding on fewer learns nothing. Two codes at Hamming
distance $H$ collide on a random $w$-subset with (hypergeometric) probability $q(H) =
\binom{d-H}{w}/\binom{d}{w} \approx (1-H/d)^{w}$. The disclosure model is label-only; communication is
linear in $N$ and scales with $T$, the only key material is the server's PRF key, and there is no
packing ceiling. \S\ref{sec:design} develops this accept model, with the full derivation of FAR, FRR,
and $T$ as functionals of $P_{\mathrm{imp}}$, into the paper's coupling theorem.

\subsection{Binary codes from real vectors}

SimHash~\cite{Charikar02} maps a vector to the signs of random hyperplane projections; for unit
vectors at angle $\vartheta$ a random hyperplane separates them with probability $\vartheta/\pi$, so
normalised Hamming distance estimates $\vartheta/\pi$ without bias. \textbf{Super-Bit
LSH}~\cite{JiEtAl12} orthonormalises the projections in blocks of the input dimension, which keeps the
estimator unbiased while reducing its variance at the acute angles that separate genuine from impostor
pairs; at block size one it degenerates to SimHash. These are the classical, matcher-agnostic bridges;
\S\ref{sec:design} shows why, under FLPSI's accept model, the choice of bridge is not matcher-agnostic
in effect, and derives the objective a bridge should be designed for.
