\section{Threat Model and Goals}
\label{sec:threat}

\paragraph{Parties and adversary.} A \emph{client} runs the extractor and quantiser locally, producing
$\xt \in \{0,1\}^{d}$; the quantiser is a trained 128-bit head whose constants ship with the model but
whose map, once fixed, is public, evaluated in plaintext on the client. A \emph{server} holds
$D = \{(\yt_i, \ell_i)\}_{i \in [N]}$ and a single PRF key $k$ shared across records and sessions. The
client learns the labels of records accepted by $\Fnpsi$; the server learns nothing ($\Fnpsi$ and its
leakage $\mathcal{L}$ are in \S\ref{sec:security}). The adversary is \emph{semi-honest} with static
corruption of one party; malicious security is out of scope (\S\ref{sec:security} sketches a path).
Security reduces to PRF security of $F$, semi-honest security of the masked OPRF and vector ring-OLE
backend~\cite{UzunEtAl21,BuiCong25}, and the LPN assumption behind the silent-VOLE
base~\cite{BoyleEtAl19,RindalSchoppmann21}. Enrolment needs an authenticated channel (otherwise an
attacker enrols chosen codes, \S\ref{sec:attacks}) and the online protocol an authenticated,
confidential one; we assume server authentication (a PKI or equivalent), which the protocol consumes
but does not provide.

\paragraph{Goals.} \textbf{G1}, the server does not learn $\xt$ or the biometric behind it;
\textbf{G2}, the client learns no more than $\mathcal{L}_{\mathsf{C}}$ of \eqref{eq:leakC}, which is
\emph{more} than ``the matched label'' and we say so; \textbf{G3}, cost linear in $N$ with no per-client
key material of consequence and no packing ceiling.

\paragraph{Deployment assumptions and scope.} Two assumptions do real work. \emph{Sensor attestation}:
since the quantiser runs client-side in plaintext, $\xt$ is a string the client chose, bound to no live
finger; deployments must attest the sensor, or security is bounded by the analysis of
\S\ref{sec:attacks} rather than biometric entropy. \emph{Rate limiting}: per-account and
per-relying-party limits are required and, at the deployed operating point, effective, since (unlike
the Super-Bit baseline) an unrelated finger is no longer accepted near-certainly at realistic $N$.
Explicitly out of scope: malicious adversaries; at-rest server compromise (the server stores $\yt_i$ in
the clear, so a read is total, \S\ref{sec:atrest}); input substitution and replay of a stolen code (not
prevented by the protocol, the attack of \S\ref{sec:attacks}); liveness/presentation-attack detection;
and client-side side channels and availability/DoS.
