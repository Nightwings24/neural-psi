\section{Conclusion}
\label{sec:conclusion}

Composing a learned extractor with fuzzy-labelled PSI the naive way, a fixed bridge tuned against an
assumed impostor law, understates the false-accept rate by $1{,}550\times$ and hits a collision floor
no sub-sampling parameters can cross. The contribution is what that diagnosis makes visible: FLPSI's
accuracy and communication are both exact functionals of one object, the impostor Hamming distribution
(\S\ref{sec:design}), so a code that minimises its variance (balanced, decorrelated bits, the objective
optimal for the protocol's own accept rule) improves both at once, on the same backend. On SOCOFing one
co-designed code lowers EER an order of magnitude (Super-Bit $1.89\%$ $\to$ feature-head $0.17\%$),
drives the collision floor to zero, and cuts matched-point communication by $45\%$, and the design rule
for its $(6,3,18)$ operating point transfers to the real \texttt{flash-psi} binary. The law is
matcher-agnostic: Lemma~\ref{lem:jensen} and Theorem~\ref{thm:variance} refer only to the impostor
Hamming law a code induces, so the objective sits between any learned embedding and any threshold-based
fuzzy matcher, and the generality results bear this out. Three directions follow: multi-corpus
validation beyond SOCOFing's same-sensor degradations (e.g.\ a cross-session corpus such as SD302);
extending the security argument to malicious clients; and replacing the Shamir/garbled-circuit
realization with the Bui--Cong ring-OLE backend~\cite{BuiCong25}, which targets the same operating
points at a better constant factor, orthogonal to our lowering of $T$.
